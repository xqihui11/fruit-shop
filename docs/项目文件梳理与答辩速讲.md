# 项目文件梳理与答辩速讲（新手版）

这份文档用于你答辩前快速掌握：

- 项目每类文件是做什么的
- 核心功能由哪些文件实现
- 请求在代码里如何流转

---

## 1. 先记住整体架构

- 前端：`frontend/src`（Vue3 + Router + Pinia + Axios + Element Plus）
- 后端：`backend/src/main/java`（Spring Boot + MyBatis-Plus + JWT）
- 配置：`backend/src/main/resources/application.yml`
- 文档：`docs/*.md`

运行时可再生成的目录（不属于源码逻辑）：

- `frontend/node_modules`
- `frontend/dist`
- `backend/target`
- `backend/hs_err_pid*.log`、`backend/replay_pid*.log`

## 2. 后端文件说明（按目录）

## 2.1 启动与通用

- `backend/src/main/java/com/fruitshop/FruitShopApplication.java`：后端启动入口。
- `backend/src/main/java/com/fruitshop/common/Result.java`：统一接口返回格式（code/message/data）。
- `backend/src/main/java/com/fruitshop/common/JwtUtil.java`：JWT 生成、解析、过期校验。
- `backend/src/main/java/com/fruitshop/common/UserContext.java`：当前请求用户上下文（ThreadLocal）。
- `backend/src/main/java/com/fruitshop/common/PasswordUtil.java`：密码处理相关工具。

## 2.2 配置与拦截器

- `backend/src/main/java/com/fruitshop/config/WebConfig.java`：跨域、上传目录静态映射。
- `backend/src/main/java/com/fruitshop/config/InterceptorConfig.java`：注册鉴权拦截器。
- `backend/src/main/java/com/fruitshop/interceptor/AuthInterceptor.java`：解析 `Authorization`，写入 `UserContext`。
- `backend/src/main/java/com/fruitshop/config/AlipayProperties.java`：支付宝参数配置载体。
- `backend/src/main/java/com/fruitshop/config/AlipayClientConfig.java`：支付宝客户端配置。

## 2.5 Mapper（数据访问层）

`mapper/*.java` 基本和实体一一对应，用于数据库读写：

- 用户与角色：`UserMapper`、`MerchantMapper`、`AdminMapper`

## 4. 基本功能“怎么实现”的（答辩重点）

## 4.1 登录鉴权（JWT）

后端链路：

1. `UserController` / `MerchantController` / `AdminController` 接收登录。
2. 对应 `*ServiceImpl` 查库校验账号密码。
3. `JwtUtil` 生成 token 返回前端。
4. 每次请求经过 `AuthInterceptor`，解析 token 写入 `UserContext`。
5. 业务层通过 `UserContext.getUserId()/getRole()` 做权限判断。

前端链路：

1. `UnifiedLogin.vue` 调登录 API。
2. token 存入 `localStorage`（用户：`token`，商家：`merchant_token`，管理：`admin_token`）。
3. `router/index.js` 根据 `meta.requiresXxxAuth` 执行路由守卫。
4. `utils/api.js` 自动给请求加 `Authorization`。

## 4.2 购物车

后端：`CartController -> CartServiceImpl -> CartItemMapper`  
前端：`Cart.vue + stores/cart.js`  
关键点：前端每次增删改后重新拉 `GET /cart/list`，确保和数据库一致。

## 4.3 下单

后端：`OrderController.create -> OrderServiceImpl.createOrder`  
实现要点：

- 校验登录和收货地址归属
- 读取已勾选购物车项
- 校验商品状态与商家一致性
- 计算总价 + 优惠券抵扣
- 新建 `Order` 与 `OrderItem`
- 更新用户券状态
- 删除购物车已下单项
- 使用 `@Transactional` 保证原子性

前端：`Checkout.vue` 组织地址、备注、优惠券后发起下单。

## 4.4 支付

后端：`PaymentController -> PaymentServiceImpl`  
实现要点：

- `createPayment` 先查是否已有待支付记录（防重复创建）
- `handlePaymentCallback` 统一处理成功/失败回调
- 成功后更新订单状态并扣库存、加销量
- 通过状态判断保证幂等（避免重复扣库存）

前端：`Checkout.vue / Order.vue / PaymentResult.vue` 使用模拟支付接口联通流程。

## 4.5 订单状态流转

常见状态（以代码为准）：

- 0 待支付
- 1 待发货
- 2 待收货
- 3 待评价
- 4 已完成
- 5 已取消

谁触发变化：

- 用户下单：生成待支付
- 支付成功：待发货
- 商家发货：待收货
- 用户确认收货：待评价
- 用户评价/定时任务：已完成
- 用户取消或超时未支付：已取消

## 4.6 公告与优惠券

- 公告：`AnnouncementController/Service` + 管理端 `admin/Announcements.vue`
- 优惠券：`CouponController/Service` + `UserCoupon` 记录用户领用/核销
- 结算时在 `OrderServiceImpl` 校验券门槛、适用范围并计算抵扣

## 4.7 聊天与消息

- 站内消息：`MessageController/Service/Mapper`
- 聊天：`ChatController/ChatServiceImpl/ChatConversationMapper/ChatMessageMapper`
- 前端页面：`Messages.vue`、`ChatDetail.vue`、`merchant/Chat.vue`、`admin/Chat.vue`

## 4.8 上传

- 后端：`FileController.upload`
- 配置：`application.yml` 的 `file.upload-path`
- 映射：`WebConfig` 暴露 `/uploads/**` 访问路径

## 5. 你明天答辩可直接讲的 3 句话

1. 项目采用前后端分离，后端是 Controller/Service/Mapper 三层，前端是 Router/Layout/View 分层。  
2. 核心闭环是“登录鉴权 -> 购物车 -> 下单 -> 支付 -> 发货收货 -> 评价售后”，关键逻辑都在 `OrderServiceImpl` 和 `PaymentServiceImpl`。  
3. 系统支持三角色（用户/商家/管理员），通过路由守卫和 JWT 拦截器做权限隔离。
